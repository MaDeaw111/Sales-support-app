# WCAT D1 Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Apps Script authentication with Cloudflare Worker + D1 authentication while leaving business-data migration for later phases.

**Architecture:** Same-origin Worker auth routes use D1 binding `DB`. Passwords use PBKDF2-SHA-256; session tokens are random, only token hashes are persisted, and the browser receives an HttpOnly cookie. The existing single-file frontend changes only its authentication transport.

**Tech Stack:** Cloudflare Workers, Cloudflare D1/SQLite, Web Crypto API, vanilla JavaScript, Node.js built-in test runner.

**Spec:** `docs/superpowers/specs/2026-08-24-d1-auth-design.md`

## Global Constraints

- D1 binding name is exactly `DB`.
- Database name is exactly `wcat-sales-db`.
- D1 database id is `f1618ec6-84b5-46bb-a2ad-b0317e561d65`.
- Session cookie name is exactly `wcat_session`.
- Session lifetime is 12 hours.
- PBKDF2 uses SHA-256 and 100,000 iterations.
- No real credentials are committed.
- Business-data `/api/gateway` remains out of scope.
